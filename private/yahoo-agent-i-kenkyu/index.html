この研究の出どころ

2026-10-10、Mits様が FHL 2026 Notes のセッションで、iPhone で撮られたスクショ（sansho_yahoo_agent_i_20261010.png）を送られ、「Yahoo! が開発している。Yahoo! は孫さんの関係している会社。孫さんは圧倒的に AI について研究している。トップランナーで、かなり意味があると思う。経営の運転台と AI-Mits の導線の参考として、Claude in Chrome でいろんな画面を巡回してスクショを撮って研究してほしい」と仰った。

この研究は、Agent i を模倣するためのものではない。孫さん系列の会社が「AI を一般生活者に差し出すときの作法」を今どう設計しているかを、画面に写っている文字どおりに取り、経営の運転台／AI-Mits を同じ目で見直すための素材にする。

1. Agent i の全体像（画面数・導線・URL 設計）

1-1 入り口は Yahoo! 検索トップの右上にある小さなアイコン

PC で https://search.yahoo.co.jp/ を開くと、検索窓の右脇に Agent i の丸いカラーアイコンが置かれている。初めてのときは「NEW Agent i ×」というバッジ付きツールチップが出る。

1-2 Agent i トップページ ── 1枚で全部を見せる

アイコンを押すと https://search.yahoo.co.jp/chat に移る。この1枚に「見出し／タスク告知／タスク3枚／入力欄＋ログイン／エージェント横一列／大型推薦カード（4〜8枚）」を全部詰めている。別ページを探しに行かせない。

1-3 2回目以降は「最近使った」を上に出す

一度でもエージェントを開くと、トップページの左下に「最近使った」が追加され、よく使うエージェントの選び直しが1タップで済むようになる。

1-4 URL 設計 ── 3種類ある

エージェント一覧（/chat/tools）から見ると、エージェントは URL の形で3種類に分かれている。

型URL パターン性格例
/chat/t/<slug>23本中 19本素のチャット画面＋その領域の例題チップfortune（占い）／job（しごと相談）／image_generator（画像生成）／counselor（人間関係）／pets（ペット）など
/chat/a/<slug>23本中 1本常時出力のウィジェット型（入力欄が主役ではない）weather_outfit（天気コーデ）
/chat/s/n?q=…&a=…23本中 3本プリセットされた質問を自動送信した後の、チャット進行途中の状態a=autos（クルマ選び）／a=weather（天気）／a=cardloan（カードローン）
エージェントは全23本（お買い物2・おでかけ1・便利ツール1・悩み相談2・ニュース情報4・エンタメ趣味4・美容健康1・マネー学び4・くらし3・スポーツ1）。カテゴリは10個。そのうち3本は実体がなく、プリセットされた質問を自動送信するだけのショートカット（クルマ選び・天気・カードローン）。画面の見た目は一本道（同じ Agent i のレイアウト）だが、裏の実装は3種類に分けているのがポイント。

観点1：初めての人が最初に見るものと、押すように作ってあるもの

最初の視線の順番

  1. 見出し「疑問や悩みをAIが解決します」（左にロゴ・ロボット顔）
  2. タスク機能が登場しました（横長バナー・右端に閉じる×）
  3. こんなタスクが登録できます（3枚の「登録」ボタン付きタイル）
  4. 知りたい事を教えてください（入力欄・右端は ログイン ボタン＝紫色のグラデーション、画面全体でここだけが派手な色）
  5. エージェント（丸アイコンの横一列、7個目に「もっと見る」）
  6. 推薦カード 8枚（カテゴリ名＋具体の疑問文＋3D 絵文字キャラ）

押すように作ってあるもの

画面の中で唯一「色が強く塗ってある場所」は、入力欄の右端にある「ログイン」ボタン（紫色のグラデーション）。それ以外は白地＋細枠＋黒文字で統一されている。初めて来た人は、入力しようとして自然に「ログイン」が目に入る。「タスク登録」ボタンも紫枠だが中は白抜きで、色の強さに序列をつけている。

「推薦カード」は時間とともに入れ替わる

初回とちょっと使った後で推薦カードの中身が変わる（1-2 と 1-3 の違い）。Mits様が撮られた iPhone のスクショにあった「宿探し／ヤフコメまとめ／推し活／レシピ」も、カテゴリの中には無く、トップページの推薦枠に出てくる種類（下記 2 で後述）。

すべての画面に出る共通フレーム

  • 左サイドバー：Agent i ロゴ／新規チャット（紫グラデ）／ログインするとできること 2 行／Yahoo! JAPAN IDでログイン／ガイドラインとヘルプ／© LY Corporation
  • 中央：各画面の中身
  • 右上：（エージェント画面では）< 戻る
  • 最下部：Agent iはAIです。回答を誤る場合があります(注意点) ── 1 ピクセルも例外なし
「新規チャット」ボタンだけが、全画面で左サイドバーの一番上に紫色で居続ける。これは「どのエージェントの中にいても、ここを押せばゼロから始められる」という退避路の視線誘導になっている。経営の運転台／AI-Mits の各画面にも「ホーム（ゼロからやり直す場所）」を1個決めて、必ず左上か左サイドバーに紫色で置くと迷子が減りそう。

観点2：無料とログインで何が違うか

非ログインでも、ほぼ全部の画面は見られる

私はYahoo! JAPAN ID でログインしていない状態で、23本のエージェントのトップ・ガイドライン・ヘルプ・タスクの説明ページまで全部開けた。見るだけなら、ログインの壁はほとんどない。

ログインが必要になる場所（画面に書いてある文言どおり）

  • チャットの内容を保存し、いつでも確認することができます（左サイドバーの説明）
  • Agent iの回答を自分好みにカスタマイズできます（左サイドバーの説明）
  • 入力欄に文字を打とうとすると、入力欄右端のボタンが「送信」ではなく「ログイン」のまま出続ける（下の 2-1 でピンポイントの吹き出しが出る）
  • タスクの「登録」ボタンを押すと、タスクを保存するためにログインが要る（登録・通知の宛先がいる）

2-1 プリセット質問を開くと「ログインするとAIに質問する事が出来ます」

非ログインでも「答えのサンプルを一通り見せる」ところまで来る。クルマ選びのように予算スライダーと選択肢タイルを見るだけ・触るだけは非ログインで出来る。自由入力して AI に自分の質問を投げようとした瞬間に、「ログインすると質問できます」の吹き出しが入力欄のログインボタンから噴き出す。無料で中身を見せきってから、入力の瞬間に初めてログインを求める。
これは経営の運転台のお客様体験に真っ直ぐ使える導線だと思う。今の運転台／AI-Mits は「使う前にまず登録してください」の圧が強い（Mits様の決定で、1st stage は AI-Mits 登録に絞っている）。登録を増やすために、Agent i の「見るだけ・触るだけは無料で全部できる／自分で入力した瞬間に初めて登録を求める」順番にすると、見た人のうち登録まで進む割合が上がる可能性がある。Mits様の判断を要すること：運転台のどの画面で「見る→触る→入力」の線を引くか（これは経営判断なので、ここでは案を出さない）。

観点3：エージェント（用途別の入口）の並べ方・名付け方

並び方

一覧ページ（/chat/tools）では生活シーンの大分類（10カテゴリ）× 2 列グリッドで並ぶ。各エージェントは「アイコン＋太字の名前（4〜7文字）＋細字の一言説明（12〜18文字）」のパターンで統一されている。

  • 名前は日常語の短い名詞：お買い物／クルマ選び／おでかけ／画像生成／しごと相談／人間関係／天気コーデ／天気／話題／熱中症／占い／エンタメ／趣味・習い事／ズバトクナビ／美容・健康／学び／ファイナンス／英語ニュース／カードローン／ペット／ファッション／くらし／スポーツ
  • 説明は「〜をお手伝いします」「〜をご案内します」「〜をサポートします」の 3 パターンに統一されている（画面に書いてある文言そのまま）
  • 新しいものには「NEW」の紫バッジが付く（宿探し・ヤフコメまとめ・英語ニュース・推し活 など）

モバイルの推薦枠と、PC のカテゴリ一覧は別物

Mits様が iPhone で撮られたスクショには「宿探し／ヤフコメ…／画像生成／推し活／レシピ」が並んでいた。しかし PC のエージェント一覧（23本）には宿探し／ヤフコメまとめ／推し活／レシピは出てこない。モバイルで見た目の最初に出る5つは「NEW・推薦」の枠に出ている別物で、一覧ページの正規の23本とは重なっていない。

個々のエージェント画面の「型」── 中身の形が領域で違う

23 本の画面を全部見た結果、「同じテンプレ」ではなく、領域の性格に合わせて4つの型を使い分けていると見える。

型特徴当てはまる画面
チップ型icon ＋ 題 ＋ 一文の説明 ＋ 絵文字つきの話題チップ 6〜8個 ＋ 例題チップ 3個 ＋ 入力欄占い・人間関係・話題・エンタメ・趣味・習い事・美容・健康・学び・英語ニュース・ペット・ファッション・くらし・スポーツ・ズバトクナビ（14本）
写真タイル型icon ＋ 題 ＋ 一文 ＋ 大きな写真タイル 4枚（タイル自体が話題を代弁） ＋ 例題チップ 3個 ＋ 入力欄しごと相談（4タイル：仕事の悩み相談・自己分析・経歴書作成・キャリア相談）／画像生成（4タイル：水彩画イラスト・特撮映画・マンガ・ピクセルアート）
ダッシュボード型見出し ＋ 現時刻の生データ（グラフ・写真・一覧） ＋ 入力欄ファイナンス（日経平均リアルタイム＋マーケット影響マップ）／お買い物（カルーセル＋画像から探す＋相談しながら探す）／おでかけ（イベント／スポット／質問／できること のセクション積み）
ウィジェット型（入力欄なし）画面を占める AI 生成コンテンツ ＋ 時間切り替え ＋ スタイル設定（入力欄がない）天気コーデ（/chat/a/weather_outfit）
Mits様の決定「1st stage は AI-Mits 登録に絞る」との接点：この4つの型は「お客様が何を欲しがっているか」で場所分けができる。
経営の運転台／AI-Mits の各領域（売上・経費・残高・LP・配信・会員）に当てはめるなら、A（相談）・B（具体例を写真で見せる）・C（ダッシュボード＝実データ出し放し）・D（ウィジェット＝今の状況を一枚で見せる）のどれを使うかを領域ごとに決めるのが有効そう。例えば「売上の今の状況」は D 型、「経費の分類相談」は A 型、「LP の実例を見せる」は B 型、「経営の見通し」は C 型、など。
これは Mits様の経営判断（運転台の中でどの領域が優先か・どれを型 D のウィジェットで出すか）を要することなので、ここでは型の整理だけに留める。

観点4：定期的に知らせる「タスク」の見せ方

4-1 トップページでの位置づけ

タスクは「Agent i があなたの代わりに確認し、お知らせする」仕組み。トップページ上部に横長バナー（タスク機能が登場しました）＋タスクタイル3枚＋ⓘ ツールチップ（タスクとは）で、3段構えで説明している。

4-2 専用の説明ページ（LP）に飛ばす

横長バナーを押すと、agenti-guide.landpress.line.me/bas_20260910/ という Agent i 公式ブログの LP に飛ぶ。LINE が運営するブログプラットフォーム（landpress.line.me）を使っているのが特徴。

タスクの要素は4つに整理されている：① 条件（キーワード・エリア・商品など）／② タイミング（毎日・毎週・毎月）／③ 通知経路（Yahoo! JAPAN アプリ・LINE アプリのプッシュ）／④ まとめ場所（マイページ）。
経営の運転台の計測・お知らせの機能設計に、ほぼそのまま当てはめられる型。
経営の運転台 と AI-Mits では、今は Mits様が「何を見るか」を Mits様自身で決める作りになっている（私が実機を触って確かめた範囲での見立て。詳しくは Mits様の運転台の設計書を見るのが正）。Agent i の「タスク」は、お客様が条件とタイミングを1回登録すると、以後 AI が勝手に見張ってアプリの通知で届けてくれるという形式。
AI-Mits の「お知らせ」や、経営の運転台の「変化があったら教える」機能に、Agent i のタスク4要素（条件／タイミング／通知経路／まとめ場所）を転写すると、「使い続ける理由」を内側に持たせやすい。
ただし、お客様に届く本番の設計は Mits様の経営判断。ここでは型の提示まで。

観点5：AI の誤りの断り方（＆ 医療・金融での線引き）

5-1 全画面に出る標準フッタ

Agent i のあらゆる画面（トップ・一覧・エージェント個別・タスク LP・ヘルプ）の最下部に、1 ピクセルも省略せず同じ文言が出る：

Agent iはAIです。回答を誤る場合があります(注意点)

「(注意点)」が青いリンクで、押すと生成AIのガイドライン（/chat/guidelines/generativeaiguideline）に飛ぶ。警告のレイヤー構造：フッタに常に薄く・押したら詳しく。

5-2 天気コーデだけはフッタ文言が違う

ウィジェット型（天気コーデ）だけは、「回答は不正確な場合があります。AI利用の注意点」と、言い回しが少し違う。他は「Agent i は AI です。回答を誤る場合があります」と自己紹介している。服装提案は毎回「正解」が存在しない領域なので、「誤り」ではなく「不正確」と言葉を変えているのが見える（画面に書かれているとおり）。

5-3 ガイドライン本体 ── プロバイダ名まで明記

注目：生成 AI は Google（Vertex AI）と OpenAI の両方を使っていると明記している。音声データだけは「Google／OpenAI への送信の対象外」と、入力の種類ごとに扱いが違うことまで書いている。プロバイダ依存を隠さずに書く姿勢は、お客様側の信頼にも、法務リスクの軽減にも効く設計。

5-4 医療領域だけは、画面の中に警告ブロックを置く

熱中症エージェントは、画面のチップより上に目立つ色の警告ブロックがある。他のエージェントには無い。

5-5 金融領域は PR 明示 ＋ 広告ポリシー

金融のお金が動く領域では、結果の中に「PR」バッジを置いて広告であることを明示し、右下に 「広告ポリシー」 を常に出している。熱中症は医療行為に踏み込まない宣言をチップより上に置く。領域ごとに警告のレイヤーを変えている（全画面フッタ → 領域特有の警告ブロック → 広告 PR マーク → ガイドライン本体）。

経営の運転台・AI-Mits との違い

比較の前提：経営の運転台のソース（/Users/nishidamitsuhiro/untendai-seiri/src/index.html）および公開ページ（https://reports.7years.life/private/untendai-kaihatsu-nagare/）は司令塔・運転台改善が持ち場。私（BA-researcher）はソースの詳細を調べていない。以下は Agent i 側の実機の観察から見える「違いの型」にとどめる。実際の運転台／AI-Mits がどう当てはまるかの判断は Mits様の経営判断。

観点Agent i（画面に写っている事実）違いの型（運転台／AI-Mits と比べての論点）
最初に見るもの見出し → タスク告知 → 入力欄＋ログインボタン（唯一の濃色）→ エージェント横一列 → 推薦カード 8枚「ログイン（＝AI-Mits 登録）」を画面の中で唯一濃色で置いているか？他の要素は白地＋細枠にして色の序列を作れているか？
無料とログインの線見るだけ・触るだけ（スライダー・タイル）は非ログイン OK。自分で文章を入力した瞬間にログインの吹き出し登録前のお客様に「中身を見せる」設計になっているか？「使う前にまず登録」の圧の方が強くないか？
入口の見た目23 本のエージェント × 10 カテゴリ。名前は 4〜7 文字の日常語の名詞、説明は「〜をお手伝いします／〜をご案内します／〜をサポートします」の3型に統一運転台の各機能の名前が、お客様の日常語になっているか？「売上」「残高」「変化」など、お客様が「それを見たい」と口に出す語か？
個々の画面の型チップ型（14本）／写真タイル型（2本）／ダッシュボード型（3本）／ウィジェット型（1本）── 領域の性格で使い分け運転台の各領域（売上・経費・残高・LP・配信）が、A〜D のどの型で見せると一番伝わるか。全部同じ型になっていないか？
定期の知らせタスク = ①条件 ②タイミング ③通知経路 ④まとめ場所 の4要素。別アプリ（Yahoo! JAPAN／LINE）のプッシュに乗る運転台／AI-Mits の「お知らせ」が、この4要素を全部満たしているか？通知経路は別アプリ（LINE 等）経由になっているか、それとも運転台に戻らないと見られないか？
AI の誤りの断り方全画面フッタ（Agent i は AI。誤りあり）＋ 領域特有の警告（医療・金融）＋ 生成AIガイドライン本体（Google／OpenAI 名入り）AI-Mits の各画面に「AI である・誤りがある」の断りが入っているか？領域ごとに警告の強さを変えられているか？
マネタイズの作法カードローンはPR バッジ ＋ 広告ポリシーで広告だと明示。他領域はまだアフィ色が無い運転台のマネタイズに広告を入れるとき、同じ「PR 明示＋ポリシー常掲」の作法を使うか
もっとも効きそうな転写は 「無料とログインの線」と「入力欄＝唯一の濃色＝ログインボタン」の2点。
