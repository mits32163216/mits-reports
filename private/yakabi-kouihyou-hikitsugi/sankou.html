拉麵屋嘉比 候位表 ── 読み上げ・会話・履歴の追加（引き継ぎ書）

宛先：屋嘉比さま / 作成：2026-10-13 / 対象：候位表 https://claude.ai/artifact/MLNSmqhUqCzUxQ4xp7WDe4（屋嘉比さまが Claude で編集される前提）

目的は3つです。① 入口の iPad で入った新しい受付を、厨房スタッフが Bluetooth の骨伝導イヤホンから「読み上げ」で聞けるようにする。② 入口と厨房で声の会話ができるようにする。③ 受付の情報が自動で消えずデータベースに残るようにする。候位表（Web）の変更は屋嘉比さまの Claude にそのまま貼れる指示文を章 ② に用意しました。

この文書の線引き
① と ③ は候位表（Web）の変更。② は iPad の設定と FaceTime の運用。候位表（Web）の中では電話機能は作れません（候位表は claude.ai のビューワ上で動く Web ページで、マイク機能を持ちません）。

① 今の候位表の仕組み（短く）

候位表は 1 枚の Web ページです。入口の iPad と厨房の iPad から同じ URL を開き、最初の画面で「入口平板（role='entrance'）」か「員工叫號機（role='staff'）」のどちらかを選びます（この選択は localStorage の yakabiKouiRole に保存されます）。両方の端末は裏側で同じデータベースを見ていて、片方が「候位」を登録すると、もう片方の画面にすぐ出ます（内部で onSnapshot という仕組みを使っています）。

データベースにある表（コレクション）は 4 つです。

表の名前何が入っているか
queueその日の受付 1 組ごとに 1 行。number, partySize, name, phone, kidsChair, status, date, createdAt, calledAt, seatedAt, cancelledAt など。status は waiting / called / seated / cancelled。
reservations電話予約。arrived が true になると「已到達（到着）」。
settings/config平均待ち分数（1 人あたり）などの共有設定。
stats/{日付}_{時刻}16:00 と 22:00 の自動片付けの直前に、その日の「組数・座った数・残った数・取消し数」をまとめて記録する集計表。

音は playChime という関数が WebAudio（ブラウザ内蔵の音源）で短い 2 音を鳴らします。今の作りでは、入口平板（role === 'entrance'）で、まだ鳴らしていない組が called（叫號中）になった時だけ鳴ります。員工叫號機（role === 'staff'）には、新しい受付が入っても音も読み上げもありません。これが「厨房スタッフが入口の受付に気付かない」の根の原因です。

checkScheduledCleanup という関数が 16:00 と 22:00 に走り、その日の集計を stats/日付_16（または _22）に 1 行書いてから、queue の各行を 1 件ずつ delete します。姓名・電話・各時刻は残りません。これが「履歴が残らない」の根の原因です。

② 候位表に足す変更（屋嘉比さまの Claude にそのまま貼ってください）

下の指示文を、屋嘉比さまが候位表を編集している Claude の会話にそのままお貼りください。関数名・表の名前・変数名はいま候位表に実在するもの（playChime / checkScheduledCleanup / queue / stats / onSnapshot / role / todayEntries / calledIdsSeen）だけで書いてあります。

指示文（コピーしてお貼りください）

以下の 2 つの変更を候位表（Claude の Artifact）に加えてください。
関数名・表の名前・変数名は現在のコードにあるものをそのまま使うこと。

── 変更 1：員工叫號機（role === 'staff'）で、新しい受付と予約の「已到達」を
中国語（台湾）で読み上げる。

既存の render() の中、role === 'entrance' のブロックで
calledIdsSeen を使って chime を鳴らしている箇所と同じ考え方で、
staff 側に「新しく出てきた組」の検出を追加する。

1) モジュールの先頭（var calledIdsSeen = {}; の近く）に、新しく足す：
     var spokenWaitingIds = {};   // 既に読み上げた候位の id
     var spokenArrivedIds = {};   // 既に読み上げた「已到達」予約の id

2) 新しく足す関数 speakZhTW(text) を定義する：
     function speakZhTW(text) {
       if (!('speechSynthesis' in window)) return;
       try {
         var u = new SpeechSynthesisUtterance(text);
         u.lang = 'zh-TW';
         u.rate = 0.95;
         window.speechSynthesis.speak(u);
       } catch (e) {}
     }

3) render() の中、role === 'staff' のときだけ以下を実行する処理を追加する
   （role === 'entrance' の chime ブロックのすぐ下あたり）：

     if (role === 'staff') {
       // 初回ロードでいま並んでいる組を全部読まないようにするための印
       if (!spokenWaitingIds.__initialized) {
         waiting.forEach(function (e) { spokenWaitingIds[e.id] = true; });
         spokenWaitingIds.__initialized = true;
       } else {
         waiting.forEach(function (e) {
           if (spokenWaitingIds[e.id]) return;
           spokenWaitingIds[e.id] = true;
           // 例: 「3號，2位，需要兒童座椅」
           var text = e.number + '號，' + e.partySize + '位';
           if (e.kidsChair) text += '，需要兒童座椅';
           speakZhTW(text);
           // 読み上げた時刻を書き戻す（後からの振り返り用）
           if (db) {
             db.doc('queue/' + e.id).update({ spokenAt: new Date().toISOString() })
               .catch(function () {});
           }
         });
       }
     }

4) 予約の reservations.onSnapshot のコールバックの中（arrived が true になったとき）
   に、同じ考え方で以下を足す。reservations の購読が staff でも動くことを確認し、
   staff のときだけ speakZhTW を呼ぶ：

     if (role === 'staff') {
       if (!spokenArrivedIds.__initialized) {
         reservations.forEach(function (r) { if (r.arrived) spokenArrivedIds[r.id] = true; });
         spokenArrivedIds.__initialized = true;
       } else {
         reservations.forEach(function (r) {
           if (!r.arrived || spokenArrivedIds[r.id]) return;
           spokenArrivedIds[r.id] = true;
           var nm = r.name || '預約';
           speakZhTW('預約的客人到了：' + nm);
         });
       }
     }

── 変更 2：checkScheduledCleanup で消す前に、各組の全項目を history 表に
写してから消す。

現在の checkScheduledCleanup は：
  db.doc('stats/' + stats.date + '_' + slot).set(stats).then(removeAll)
の順で、集計を書いてから各行を delete している。

removeAll を次のように差し替える：
  var removeAll = function () {
    entries.forEach(function (e) {
      // 1 組の全項目を history に写す
      var copy = {};
      for (var k in e) { if (Object.prototype.hasOwnProperty.call(e, k)) copy[k] = e[k]; }
      copy.archivedAt = new Date().toISOString();
      copy.archivedSlot = slot;      // '16' または '22'
      copy.sourceId = e.id;
      if (db) {
        db.doc('history/' + e.id).set(copy)
          .then(function () { db.doc('queue/' + e.id).delete().catch(function () {}); })
          .catch(function () {
            // 書き込みに失敗した時は、queue からは消さない（データ消失を避ける）
          });
      }
    });
  };

これで、16:00 と 22:00 に queue の行は消えても history 表に全項目が残る。
今まで通り stats にはその日の集計も残る。既存の UI は書き換えない。

員工叫號機の画面を初めて開いたとき、スタッフは画面のどこかを 1 回タップしてから
日常運用に入ってほしい。
この指示文の裏付け（確認済み）
iOS 27 の iPad Simulator の Safari で、speechSynthesis.getVoices() は zh-TW の声として Meijia を 1 件返しました。speak() の呼び出しで onstart / onend も発火しています。章 ⑥ のテスト写真をご覧ください。

③ 厨房の iPad の設定（写真つき）

員工叫號機を出す iPad を、画面が勝手に消えないように、他のアプリに移らないように設定します。この章は、設定アプリの「どこを開くか」を日本語と繁體中文で並べて書いてあります。

3-1. 自動ロック：なし（画面を点けっぱなしにする）

設定場所の名前（iPad OS で言語を切り替えると文言が変わります）：

  • 日本語：設定 → 画面表示と明るさ → 自動ロック →「なし」
  • 繁體中文：設定 → 顯示與亮度 → 自動鎖定 →「永不」
Simulator に無かった ── 実機でご確認ください
2026-10-13 に iOS 27 の iPad Simulator（iPad Air 11-inch, M4）で設定アプリの検索を試しました。日本語で「自動ロック」、繁體中文で「自動鎖定」、英語で「Auto-Lock」を打っても どの言語でも検索結果はゼロ でした（下の写真）。「画面表示と明るさ／顯示與亮度／Display & Brightness」の項目自体がシミュレータの一覧に出ていません。これはシミュレータが実機のディスプレイを持たないからで、屋嘉比さまの実機の iPad では、必ずこの項目があります。実機で「画面表示と明るさ → 自動ロック →『なし』」を選んでください。

3-2. アクセスガイド（候位表の画面から離れないようにする）

アクセスガイドをオンにすると、1 つのアプリに画面を固定でき、ホームへのスワイプや他アプリへの移動を遮断できます（屋嘉比さまが決めた暗証番号を入れないと解除できない仕組み）。

  • 日本語：設定 → アクセシビリティ → アクセスガイド → オン
  • 繁體中文：設定 → 輔助使用 → 引導使用模式 → 開啟
Simulator に無かった ── 実機でご確認ください
iOS 27 Simulator は「アクセスガイド／引導使用模式／Guided Access」の子項目を持っていません。実機の iPad では「アクセシビリティ」を下にスクロールすると「一般」のまとまりの中にあります。

アクセスガイドを使うときは、候位表（Safari のページ）を開いた状態で、サイドボタンを 3 回連続で押すと開始／終了できます（これは Apple 標準の操作です）。

3-3. 自動で電話に出る（イヤホンでそのまま応答する）

  • 日本語：設定 → アクセシビリティ → タッチ → 通話オーディオルーティング →「自動で電話に出る」をオン
  • 繁體中文：設定 → 輔助使用 → 觸控 → 通話語音路由 →「自動接聽來電」開啟
Simulator に無かった ── 実機でご確認ください
iOS 27 の iPad Simulator は電話／通話機能を持たないため、「アクセシビリティ」の「身体機能と動作サポート（身體動作）」の中が空です。実機にはそこに「タッチ／觸控」があり、その中に「通話オーディオルーティング／通話語音路由」があります。写真は章 3-2 と同じアクセシビリティ画面を見返してください。
また、章 ⑥ で後述するとおり、Apple の公式ガイドは「自動で電話に出る」の機能が FaceTime の着信に効くとは明記していません。本番運用の前に実機で FaceTime 通話を 1 本かけて、骨伝導イヤホンに届くかをご確認ください。

④ イヤホン（Shokz OpenComm2）

厨房スタッフが使う骨伝導イヤホンは Shokz OpenComm2（ブームマイク付き）です。耳をふさがないので、厨房の音を聞きながら読み上げを聞けます。公式仕様の要点は 3 つです：

  • 接続できる距離：最大 30 m（iPad と厨房スタッフの間で遮蔽物がなければ）
  • 連続通話：最大 16 時間（1 日 1 回の充電でも足りる）
  • 2 台の機器に同時接続（マルチポイント）

厨房スタッフが複数名いる場合は、スタッフ 1 人につき 1 つの iPad と 1 つの OpenComm2 が必要です。iPad 1 台から複数のイヤホンに同じ音を鳴らすこと（「オーディオを共有」）は、Apple の AirPods / Beats 同士では可能ですが、OpenComm2 を含む第三者イヤホンではできません（出典は末尾 Apple サポート dev3786f35c8）。

したがって運用は「員工叫號機の候位表を、厨房スタッフが使う iPad 1 台ごとに 1 画面ずつ開く」になります。

⑤ 入口との会話（FaceTime オーディオ）

候位表（Web ページ）の中では、入口と厨房の声の会話は作れません。候位表が置かれている claude.ai の Artifact は、Mits さまが参謀にご指示されたとおり、マイクを扱う仕組みを持っていません。

そこで会話は Apple 標準の FaceTime オーディオで行います：

  1. 入口と厨房の iPad を、それぞれ屋嘉比さまご本人の Apple アカウントでサインインしてください（連絡先に相手の Apple アカウントを登録）。
  2. 入口の iPad で：
    日本語：設定 → アクセシビリティ → タッチ → 通話オーディオルーティング →「自動で電話に出る」をオン（応答までの秒数は 0 秒〜短めに）。
    繁體中文：設定 → 輔助使用 → 觸控 → 通話語音路由 →「自動接聽來電」開啟。
  3. 厨房のスタッフが、骨伝導イヤホンのマイクで FaceTime をかけます。入口の iPad は人が触らなくても自動で応答し、厨房の声は入口の iPad のスピーカーから出ます。入口のお客さまの声は入口の iPad のマイクが拾い、厨房のイヤホンに届きます。
Simulator に無かった ── 実機で必ず試してください
章 3-3 のとおり、iOS 27 Simulator には「タッチ／觸控」自体が無く、「自動で電話に出る」をオンにするところまで Simulator では確認できていません。Apple のサポートガイド ipad11dbabaf は「自動で電話に出る」が FaceTime の着信に効くとは明記しておらず、別ガイド ipada16d1374 も「オーディオの出力先」の話題と並べて書かれています。本番運用の前に、必ず屋嘉比さまの実機で 1 本 FaceTime をかけて、ベルが数秒鳴ったあと勝手に繋がるかをご確認ください。

⑥ 店で確かめる項目（本番前の 4 項目 + 2 項目）

  1. 「自動で電話に出る」が FaceTime 通話に効くか ── 入口の iPad を触らずに置き、厨房の iPad から FaceTime をかけ、設定した秒数で勝手に繋がり、厨房のイヤホンで会話できるか。Apple のガイドは電話／通話一般の話であって、FaceTime に効くとは明記していません。
  2. 候位表の読み上げ（音）と、FaceTime の相手の声が、同時にイヤホンから出るか ── 厨房スタッフが FaceTime 通話中に新しい受付が入った瞬間、読み上げが FaceTime 側に遮断されないか、または FaceTime がミュートされないか。
  3. アクセスガイド中に FaceTime を受けられるか ── アクセスガイドで候位表を固定している最中、FaceTime 着信画面が前に出るか／自動応答がそのまま効くか。
  4. 「オーディオを共有」が OpenComm2 でできないことの確認 ── Apple のサポート（dev3786f35c8）は AirPods と Beats の対応モデル同士に限ると書いていますが、現場でそのとおりかを 1 回だけ検証して、厨房スタッフが複数名の場合は「1 iPad 1 OpenComm2」運用で揃えてください。
  5. 員工叫號機の初回タップ ── iOS Safari では、ページを開いた直後の自動呼び出しだけでは speechSynthesis がブロックされることが報告されています（WebKit バグ #223473）。章 ② の指示文のとおり、スタッフは員工叫號機の画面を一度だけ画面上のどこかをタップしてから運用に入ってください。章 ⑤ の Safari テストでは、ユーザが画面上の「Speak now」をタップした直後は、onstart / onend まで正常に発火しています。
  6. 履歴の見える場所 ── 変更 2 を入れた後、1 回目の 16:00 片付けが走った翌日、history 表に当日の全組の記録（氏名・電話・各時刻）が入っているか。Claude の会話で「history 表を見せて」とご指示ください。
