流れを一言で：直しはいつも main に入れる → main から4本を組む → Mits様の製品版に「自分だけ」で入れて溜める → Mits様が触って OK、「出す」と言われたときだけ世に出す。
freee版を製品版に「組み込む」作業は、もう無い。freee の枝は 2026-09-25 に main へ入り、それ以後 freee版は main から別の名前で組んでいる。製品版と freee版は同じコード。

4. 言葉を2つに分ける（2026-09-14 Mits様確定）

Mits様：「いつもAIがいう『世に出します』をどの内部基準をもつかだな。つまり、製品版だけど実質自分だけが見るにとどめて、まとめて『世に出す』」「OK、それをルールにしよう」
言葉何が起きるかお客様に届くか道具
Mits様の製品版に入れる版を上げて commit・タグ・push、Mac を組んで /Applications/untendai.app だけ入れ替え届かないbash tools/release.sh --自分だけ <版> "<要約>"
世に出すGitHub に Release を作り、latest.json を新しい版にする全員に届くbash tools/release.sh <版> "<要約>"
手渡し（freee版）zip を相手のフォルダに置き、Mits様が共有するその相手だけbash tools/build-client.sh

世に出すのは2つのときだけ。①Mits様が製品版で触って「出す」と言われたとき ②お客様の手元で数字が間違っている・取り込みが止まっているとき（溜めずに出す）。

いまの製品版 1.74.1 を世に出すと、お客様全員の製品版にも「freee との連携」と管理者スイッチが出る。

5. 手順（いま実際に回している形）

5-1. 直しを入れる

  1. 画面の直しは モックを作る → Mits様が目視 → 実装 の順（2026-08-29）。モックは明るい画面で Chrome で開く
  2. main（~/untendai-seiri）に commit する。他の人がまだ commit していないファイルは入れない・戻さない
  3. 含めたい直しを git add してから組む（2026-09-26・版が2つ出た事故から）

5-2. Mits様の製品版に入れる

bash tools/release.sh --自分だけ 1.74.2 "直しの要約"
bash tools/build-dev.sh          # 開発版も同じ main で組み直す（--自分だけ は開発版を入れ替えない）
  • 入れたあと、タグの中身と入っているアプリの中身を突き合わせる（2026-09-26・1日で3回ずれた）
  • 動いている製品版が古いまま残ることがある。起動の時刻が組んだ時刻より前なら、閉じて開き直す（2026-10-01 に実際に起きた）
  • 確かめる：curl -s https://untendai-update.3216-fun.workers.dev/latest.json の version が変わっていない＝世に出ていない

5-3. freee版を手渡す（協力者・コンサルタント）

  1. bash tools/build-client.sh で main から組む。おまけの実行ファイル（demo_seed_cred）は外す
  2. 実データの検査（下の 6）を全部通す
  3. 何も入っていない状態で開いて、案内の写真を1手ずつ撮る（この Mac の freee版のデータは先に退避し、撮り終えたら戻す）
  4. 写真どおりに「はじめに読んでください」を書き、BS-jikki-kenshu の検収に通す
  5. 相手のフォルダ（すごいコンサル/<お名前>/）に zip・案内・画像を置く
  6. 共有と連絡は Mits様

5-4. 世に出す（Mits様の「出す」のあと）

bash tools/release.sh <溜めた最後の版> "要約"

手1〜4（版・push・Mac）は済み判定で飛ばし、手5 Windows・手6 Release・手7 latest.json から走る。
