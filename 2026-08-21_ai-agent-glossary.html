AIエージェント 用語集
——「難しい言葉」を全部ほどく

発行: 2026-08-21 / 対象: AIを仕事の道具として使いたい人（プログラムを書かない人を含む）
出典: 対談「コーディングAIエージェントブームは終わった」（牛尾剛さん／NewsPicks）

はじめに

難しい言葉は、たいてい「規模が大きい会社の話」の顔をして出てきます。中身をほどくと、ひとりで働く人にも同じ形で当てはまります。

  • 大卒文系の理解力で読める言葉に置き換えました。専門用語は1つも飛ばしていません
  • 切り捨ての線は「組織か、ひとりか」ではありません。「作る側か、使う側か」です。作る側の実装だけが不要で、使う側の原理は規模を問わず効きます
  • 置き換えが効く用語には「ひとりで働く人の場合」の欄を付けました
  • 第5章には、実際に起きた事故を2件載せています ✅確認済

1. 土台の語

上から順に積み上がる並びです。ここが分かれば、あとは全部この応用になります。

生成AI

文章・画像・音声などを新しく作り出すAIの総称。「判別するAI」（迷惑メールか否かを分ける等）と区別するための言い方。

モデル

AIの頭脳そのもの。会社ごと・世代ごとに別物で、賢さと値段が違います。「高性能なモデル」「安いモデル」「新しいモデルが出た」は全部これを指します。

LLMLarge Language Model／大規模言語モデル

モデルのうち、言葉を扱うもの。大量の文章を読み込んで「次に来る言葉」を確率で当て続ける仕組みです。

学習（訓練）

モデルを作るときに、大量の文章を読ませて中身を作り込む工程。使う側が会話した内容は、原則この学習には入りません。「うちの会社の事情は学習しようがない」と言われるのはこの意味です。

推論

学習済みのモデルに質問して答えを出させること。私たちが日常でAIを使っている行為は、全部こちらです。

自然言語

プログラム言語ではない、普通の人間の言葉。「所詮は自然言語だから簡単」＝日本語で書けるから誰でも作れる、という意味です。

プロンプト

AIへの指示文。人間が打ち込む「これやって」の一文です。

トークン※2つの全く別の意味で使われます

混同が最大の事故源です。

料金の単位としてのトークン
文章を細かく割った最小単位。日本語で1〜2文字ほど。AIの利用料はこの個数で決まります。
鍵としてのトークン
本人確認のための文字列。合鍵そのものです。料金とは何の関係もありません。

「トークンが高い」なら料金、「トークンを渡す」「トークンが違う」なら鍵の話です。

クレデンシャル

認証情報の総称。合鍵・身分証にあたるもの全般（ID、パスワード、鍵としてのトークン）。

コンテキスト（コンテキストウィンドウ）

AIが今この瞬間に見えている情報の範囲。人間で言えば机の上に広げてある資料です。ここに載っていない情報は、AIにとって無いのと同じ。そして容量に上限があり、超えると古いものから押し出されます。

APIApplication Programming Interface

機械同士が話すための窓口。人間が画面をクリックする代わりに、プログラムが直接AIに注文を出す入り口です。「窓口の作りが世代交代して、自分で作業を続けるAIに向いた形になった」という話が対談に出てきます。

ハルシネーション

AIが、もっともらしい嘘を自信たっぷりに答えること。「100%正しいとは限らない」「意外と抜けている」はこれを指しています。

ローカル／クラウド

自分のパソコンの中で動かすか／向こう側のサーバーで動かすか。対談の最大の対立軸です。

サーバー

常時動いていて、頼まれた仕事を処理する機械。自分のパソコンと違い、閉じたり持ち歩いたりしません。

CLI／GUI

文字を打って操作する画面（CLI）と、マウスで押して操作する画面（GUI）。エンジニアが好むのは前者で、速く、自動化しやすいためです。

ヘッドレス

画面を一切出さずに動かすこと。人間が見ていないところで、裏で黙々と走っている状態です。

2. エージェント関連

エージェント

指示を1回受けたら、あとは自分で考え、道具を使い、何度も試し、最後までやりきるAI。「答えるAI」ではなく「作業するAI」です。

コーディングエージェント

そのうちプログラム作成に特化したもの。

サブエージェント

エージェントが自分の下請けとして呼び出す、もう一段下のAI。細かい作業を担当させ、安いモデルを割り当てて費用を下げる使い方をします。

スキル

AIに渡す「うちのやり方マニュアル」。プログラムではなく普通の日本語の文書です。

AIは世界の一般知識を持っていても、あなたの商売の作法だけは持っていません。ここだけが人間にしか作れない資産で、普通の言葉で書いてあるので引っ越しも一度で済みます。

エージェント定義

そのAIが何者で、何を担当し、何をしてはいけないかを書いた設定文書。スキルが「やり方」なら、こちらは「役割」です。

スキルレジストリ

作ったスキルを、みんなが探して使えるように登録しておく置き場。

ひとりでも要ります。半年前の自分は他人で、探せない資産は無いのと同じだからです。

アセット

資産。この対談では具体的に溜め込んだスキルとエージェント定義を指します。

MCP

AIを外部サービス（保存先・記録・連絡手段など）に繋ぐための共通の差込口の規格。USB端子の規格にあたるものです。

繋ぐほど、資料を毎回貼り付ける手間が消えます。まず保存先とメールの2つで十分です。

ハーネス

直訳は馬具。AIに道具を使わせ、暴走を防ぐための囲いと土台です。

唯一、自分で作らなくてよい項目。既製品がすでに土台です。理由は規模ではなく「買えるものを作るのは損だから」。

エージェントワークフロー

複数の作業を順番に並べてAIに流させる仕組み。

十徳ナイフ（たとえ）

1本で何でもやろうとする道具。「料理するなら包丁を使う」＝用途ごとに最適な道具を選べ、という主張です。

文房具（たとえ）

騒ぐ対象ではなく、必要なときに手に取る当たり前の道具になった、という意味です。

3. 開発の道具

対談で前提として飛び交う語です。意味を知らないと会話の半分が読めません。

エディター

プログラムを書くための画面。「AIはエディターと同じくらい当たり前になった」の比較対象です。

リポジトリ／クローン

プログラムの保管庫（履歴つきで管理される）／それを丸ごと手元に複製すること。

プルリクエスト／マージ

「この修正を取り込んでください」という申請／それを実際に取り込むこと。AIが自分の間違いに気づいて、自分の手順書の修正案を出してくる——これが対談で言う学習の輪の完成形です。

Git／GitHub

Gitはプログラムの版を管理する仕組み。GitHubはそれをみんなで共有する場所。最初は各自の手元だけだったものが、共有の場所に集約されていったという歴史が、「AIも同じ道を辿る」の根拠に使われています。

コンテナ／公開の倉庫

プログラムを実行環境ごと箱詰めして、どこでも同じように動かす仕組みと、その箱を配っている公開の置き場。

内部の倉庫／検査

外部の公開倉庫から直接取らず、いったん社内に置いた検査済みの倉庫からだけ取る仕組みと、その検査。

デプロイ

作ったものを実際に動く場所へ配置して稼働させること。

プレビュー

正式公開の前の試験提供。一部の利用者が先に触れる段階です。

4. 安全と権限

組織向けに見えますが、ひとりで働く人にも「見せてよい相手／悪い相手」は実在します。外注のライター、外注のデザイナー、そしてAIです。

ユーザートークン

本人がログインして使う、権限の強い合鍵。人間が手で操作する前提の強さがあり、AIに渡すのが危険とされる理由です。

AIにこの鍵を握らせない。乗っ取られたら自分にできること全部がやられます。

役割ごとの権限分離RBAC

「この役割の人はここまで」と、見える範囲・触れる範囲を役割単位で切る仕組み。

外注さんに見せない顧客情報を、AIには見せていないか。サービスごとに権限を絞った鍵を発行して渡します。

自動処理専用の身分証managed identity

人間用ではなく、機械が自動で動くために発行された、最初から権限の狭い鍵。

自動で走らせる処理は、本人ログインに頼らない。本人ログインは期限切れで黙って止まります。

部品経由の攻撃サプライチェーンアタック

AIが外から拾ってきた部品に毒が仕込まれている型の攻撃。

素性の知れない拡張機能・接続部品を入れない。判断する人が自分しかいません。

認証／認可／アイデンティティ

認証＝本人であることの確認。認可＝その人に何を許すかの判定。アイデンティティ＝誰であるかの情報そのもの。3つは別物で、対談で「ここが大きな問題」と言われている箇所です。

サンドボックス

使い捨ての隔離部屋。中で何が起きても外に影響せず、終われば消えます。

乗っ取られる

AIが細工された指示を読まされて、攻撃者の言うことを聞いてしまう状態。

統制／把握されていない道具

誰が何をどこまでやってよいかの管理／会社が把握していないところで勝手に道具が使われている状態。

5. 障害対応 —— 実例つきで、ひとりの現場に置き換える

この章は全部の語がそのまま置き換わりました。ひとりで働く人の障害とは、申込フォームが動かない・配信メールが飛ばない・決済が通らない・ページが崩れる・自動処理が黙って止まる、です。

規模が小さいのではありません。誰も見ていないぶん重い。

実例①：同じメールが7通届いた（2026-08-18） ✅確認済

  • 何が起きたか：朝8:00〜8:01、同じメールが受信箱に7通
  • 原因：10日前の夕方、ページの動作確認でテスト用アドレス4種を計10回登録。読者データが10個でき、10日後に届く設定のメールが読者ごとに1通ずつ発火した
  • 気づいたきっかけ：自分が受信者だったから。監視でも通報でもない
  • 気づくまで10日。止めるまで即日。

実例②：差し込み文字が置き換わらないまま103通届いた（2026-08-14） ✅確認済

  • 何が起きたか：本文の差し込み文字（お名前や日程を自動で入れる記号）が、記号のまま顧客に届いた
  • 原因：AIが根拠なく作り出した記号名だった。手順書に出典なしで書かれ、4ヶ月のあいだ誰も検証しないまま残っていた
  • 気づいたきっかけ：顧客からの指摘
  • 制約：配信し終えたものは後から直せない。潰せるのは配信待ちのものだけ

インシデント

障害・トラブルの発生。

上記2件そのもの。顧客の受信箱に直接届く型なので、被害が即時です。

SRE落とさず動かし続ける専門職

サービスを止めないことを専門にする職種・分野。

この役を誰も持っていません。役として時間を先に確保しない限り、永久に後回しになる領域です。

一次窓口

世界中から上がった障害をまず調べ、手に負えないものだけを開発チームへ回す部門。

実例①は自分の受信箱、②は顧客の指摘が一次窓口でした。2件とも一次窓口が人間。ここを自動の見張りにしていれば、①は当日に分かっていました。

オンコール待機当番

夜中でも呼び出しに応じる担当。

交代相手がいないので常時当番になります。だからこそ「何が起きたら呼ばれるか」を決めておかないと、24時間気が休まらない。決めることは、休むための作業です。

根本原因の特定RCA

「なぜ落ちたか」の犯人捜し。

直して終わりにしがちです。原因を書き残さないので、半年後に同じことが起きて、また同じ時間を使います。実例②の真の原因は「記号名の間違い」ではなく登録の経路の違いでした。表面で止めていたら再発します。

ミティゲート応急処置で血を止める

原因の完全解決ではなく、まず被害を止めること。原因究明とは別工程として先に行います。

この分離が最大の応用です。原因を調べている間に顧客は離れる。順番は「まず止める、それから調べる」。混ぜると両方遅れます。

止まるまでの時間time to mitigate

発生から血が止まるまでの時間。短縮すべき指標です。

測るのは2つ。気づくまでの時間と止めるまでの時間。実例①は10日と即日でした。削るべきは後者ではなく前者。桁が違います。

担当の付け替え

自分の領域ではないものを、別の担当へ回すこと。

抱え込まない判定。外注・道具の提供元・専門家のうち誰の領域かを、最初の5分で切り分けます。

エスカレーション

上位・別担当へ引き上げること。

投げ先を事前に決めておく。起きてから探すと、そこで数時間が消えます。

記録を掘る検索

膨大な記録から「その瞬間に何が起きていたか」を掘り出すための検索。昔のAIはこれを書くのが苦手でした。

配信履歴・アクセス記録・決済履歴・実行記録。「何が起きたらどこを見るか」を先に決めておくのが、この語の実体です。

ヒューマン・イン・ザ・ループ人の確認を挟む設計

全自動にせず、要所で人が判を押す形。

顧客に届く直前だけ自分が見る。それ以外は通す。ここを決めないと、自動化しても結局全部見ることになります。実例②は、確認の置き場所が間違っていた事例です。

確信度の数値

AIが自分の答えにどれくらい自信があるかを数値で出したもの。低いものだけ人間が見る振り分けに使います。

判断の回数を減らす道具。AIに「これは自信が低い」と言わせ、それだけ自分が見ます。

部分的に正解partially correct

完全な答えではないが、犯人がここまで絞れている状態。対談では5割が正解、3割がこれで、合計8割が役に立つという数字が出ています。

完璧でないことを理由に自動化をやめない根拠。8割絞れていれば、2時間が数分になります。

絞り込み

候補を狭めること。

原因の候補が3つまで絞れた時点で、もう価値が出ています。

解決済み

ここで初めて「AIの答えは正しかったのか」が判明するため、学習の起点になります。

事故の瞬間には正解が分かりません。解決した瞬間が、記録を残す唯一の好機です。

学習サイクル

解決後にAIが自分の答え合わせをし、外していたら自分で手順書の修正案を出してくる流れ。この対談の実装上の核心です。

直した後、手順書に1行足す。これだけで大企業が作っているものと構造は同じになります。

この2件が示していること

残っている穴は1つだけです。一次窓口が人間であること。

応急処置と原因究明の分離、事後の答え合わせ、記録の蓄積は、すでに実行されていました。実例①の10日間は、見張りが1本あれば消えていました。

6. 基盤と設計

対談の後半。費用と、途中で落ちない仕組みの話です。

サーバーレス／使っていない間はゼロ円

サーバーの管理を全部任せ、自分は中身だけ書く方式。使っていない間は規模がゼロ、つまり料金がかかりません。

固定費を増やさずに自動化できる。固定費の増加を最も恐れる立場に、最も効く話です。

イベント駆動／時刻での起動

人間が開始を押すのではなく、何かが起きた瞬間に勝手に動き出す方式。障害の発生・時刻の到来・申込の着信などが引き金になります。

自分のパソコンを起点にしないの実装。持ち歩いている間も仕事が進みます。

途中で落ちても続きから／長時間の処理

機械が壊れても再開できる仕組みと、何時間・何日もかかる処理を落ちずに走らせ続けること。「2日後に返ってきてもいい」。

手順の図DAG

「AをやってからBとCを並行、両方終わったらD」という手順の図。1つ1つの作業が点で、失敗したものだけやり直せます。AIに先にこの図を描かせてから走らせると、無駄な試行錯誤が減って費用が下がります。

いきなり書かせず、まず構成を出させる。費用も品質も改善する、最も安い一手です。

従量課金／上限設定

使った分だけ払う方式と、使いすぎを止める上限。

引っ越しマイグレーション

別の環境へ移すこと。スキルは普通の言葉で書いてあるので、引っ越しが一度で済むのが利点です。

中身を隠して入口だけ使わせる設計

昔のAIに検索文を書かせるのが難しかったので、この形で逃げた、という話です。

使うAIの振り分け

難易度に応じて、高性能な高いAIと安いAIを自動で使い分けること。「これを人間が毎回選ぶのが面倒」という問題提起が対談に出てきます。

自作はしない。ただし軽い仕事に高いAIを使わない判断は今日からできます。

7. 仕事論

ROI投資対効果

かけた金と時間に対して、どれだけ返ってきたか。

優先度（P0／P1／P2）

P0が最重要。「優先度の低い仕事をたくさん並列でこなしても価値が薄い」という文脈で使われます。

ボトルネック

全体の速度を決めてしまう、一番狭い箇所。この対談では人間の判断がそれだとされています。

判断する人が1人しかいないため、大きな組織より効きます。

レバレッジ

てこ。少ない力で大きな結果を出す効き方。「本体を鍛えるほうが効く」。

コモディティ化

誰でもできる当たり前の技能になり、価値が下がること。並列でたくさん回す能力は、これになるというのが対談の読みです。

並列で走らせる

AIを何本も同時に動かすこと。

並べても、判断する自分が追いつきません。並べる前に、判断が要らない形に直すのが先です。

その分野の固有知識

その業界・その会社に固有の事情と勘所。AIが最も苦手とする領域で、唯一の資産になる場所です。

車輪の再発明

すでにあるものを知らずに一から作り直す無駄。

ひとりでも起きます。半年前の自分が同じものを作っている。

アジャイル／スクラム

短い期間で作って直すことを繰り返す進め方と、その代表的な型。「導入すれば10倍の生産性。ただし駄目な人は10倍の速さで駄目なものを作る」という逸話の出どころです。

一次情報／二次情報

本人が直接得た情報／誰かがまとめ直した情報。AIが出すものは常に後者、というのが対談の最後の主張です。
